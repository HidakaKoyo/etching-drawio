# Security

What this project defends against, what it only detects, and what it does not
try to do at all. Normative behaviour lives in `contracts/`; this document is
the reasoning around it.

## Threat model

`etching-drawio` runs on a developer's machine, under an agent, on files that
machine already has. It has no server, no credentials, no network access at run
time, and no persistent state beyond the files it is told to write. The
interesting exposures are therefore three:

1. **A hostile or malformed `.drawio` input** — a file received from someone
   else, or generated by a model, and then parsed and exported by tools running
   with the user's own privileges.
2. **The supply chain of the vendored upstream references** — text that an
   agent reads as instructions before it writes a diagram.
3. **Data leaving in an artifact** — content that ends up inside a delivered
   SVG that the author did not intend to publish.

Everything below is one of those three.

## 1. Input handling

The input is parsed before draw.io Desktop is ever launched, and a document
that fails these gates never reaches it.

| Defence | Behaviour |
|---|---|
| XXE | A document declaring a DTD is refused outright (`input/dtd-forbidden`), and external entities are refused (`input/external-entity`). Refusal comes before parsing rather than from a hardened parser, so there is no parser configuration to get wrong. |
| Decompression | A compressed diagram payload is refused (`input/compressed-payload`), never inflated silently. The policy is always on and has no profile key, so no configuration can turn it off. |
| Resource exhaustion | Limits on bytes, node count and nesting depth (`input/too-large`, `input/too-complex`), applied before the document is walked. |
| External references | `http`/`file` URLs inside `style` and `image` attributes are reported under `security/external-ref` as warnings. `--allow-external` skips the check with a recorded waiver; the skill is required to report having used it. |

External references are a warning rather than an error because a legitimate
diagram may reference a corporate image host, and blocking that would push
users to `--allow-external` as a habit. The value is in the report, not in the
refusal.

## 2. Supply chain

The skill reads vendored upstream text as authoring instructions, which makes
that text part of the attack surface: a tampered reference could tell an agent
to do something the project never sanctioned.

- The snapshot is pinned to a commit SHA in `skills/etching/vendor.lock`, with
  per-file SHA-256, git blob ids, git modes and tree oids.
- `scripts/verify-vendor.py` runs in every CI job and fails on any difference.
  It repairs nothing: a difference is either tampering or a hand edit, and both
  should stop the build.
- Updates never happen in place. `scripts/propose-upstream-update.py` resolves
  a candidate commit, re-derives the dependency closure at that commit,
  downloads a candidate snapshot, and reports the difference. A weekly CI job
  runs it read-only and opens an issue when upstream moves; adopting the change
  is a reviewed commit.
- The closure is derived, not hand-listed: absolute upstream URLs are followed
  to a fixpoint (`docs/closure-allowlist.md`). A file that upstream starts
  pointing at is noticed rather than missed, and a path that disappears is a
  failure rather than a warning.
- The snapshot is byte-identical to upstream. Where this project disagrees with
  it, the override is written in the skill's own `SKILL.md`. That keeps the
  verification simple — any difference is wrong — instead of maintaining a set
  of sanctioned edits.

No code is vendored, only Markdown and an XSD; nothing from upstream is
executed.

## 3. What leaves in an artifact

- `--embed-xml` puts the full editable diagram inside the exported SVG,
  including layers that are not visible in it. It is off by default, and the
  skill is told to use it only for internal round trips and to report when it
  did.
- Receipts record hashes, versions and check results. They do not record
  document content.
- The tool sends nothing anywhere. There is no telemetry, no update check, and
  no network call in the CLI or the skill.

## 4. Concurrency: prevented, or merely detected

Between writers that go through this tool, concurrent modification is
*prevented*. The source hash is captured at the start of a run, re-compared
immediately before the master is replaced, and compared again before the
`current` pointer moves. Either mismatch stops the run with exit 3 and
publishes nothing (`contracts/delivery.md` §2.1).

Against a writer that does not go through the tool — draw.io Desktop with the
same file open, an editor, another process — it is only *detected*. There is a
window between the last comparison and the pointer move that no hash check can
close without a lock, and v1 has no lock: a stale lock is a worse failure mode
than a detected conflict. What the tool guarantees instead is that the receipt
records the source hash, and `etch verify` compares it against the file on
disk, so a conflict is reported rather than assumed away.

Where a human is expected to be editing the same file, `proposal_mode` avoids
the question: the master is not replaced and the pointer is not moved.

## 5. Filesystem behaviour

- A generation is built in `generations/<id>.tmp/`, on the same filesystem, and
  becomes visible only by rename. A reader never sees a partial generation.
- Readers resolve `current` **once** and read everything from the immutable
  directory it names. Re-resolving per file could mix two generations.
- Automatic cleanup touches only `.tmp` directories this process created.
  Another process's `.tmp` is never removed on age alone, because ownership
  cannot be determined. Completed generations are removed only by an explicit
  `etch gc --delete`, and the contract states plainly that the CLI cannot know
  whether someone is still reading one.
- The tool does not create the output root. A missing directory is a usage
  error, not a thing to be materialised.

## 6. Not in scope

- **Rendering-level analysis.** A diagram whose edges cross or whose labels
  overlap passes validation. Whether the diagram means what was intended is a
  question for a human looking at the picture, and the skill says so.
- **Sandboxing draw.io Desktop.** It is launched as an ordinary child process
  with the user's privileges, the way the user would launch it themselves.
- **Protecting against a hostile local user.** File permissions are the
  operating system's job.
- **Secret detection in diagram content.** The tool does not read the meaning
  of your labels.

Open an issue at https://github.com/HidakaKoyo/etching-drawio/issues. For
something that should not be public, use GitHub's private vulnerability
